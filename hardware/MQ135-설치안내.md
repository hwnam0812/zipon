# 집온 자동 감지·LED·부저 USB 연결 안내 — V3

## 이번 변경

기존 GP2Y1014AU0F 먼지 센서를 제거하고, 사용자가 확인한 **MQ-135 4핀 모듈(VCC / GND / AO / DO)**의 아날로그 출력을 읽습니다. 금속 캡만 있는 6핀 단품용 배선이 아닙니다. 보드 핀은 **Arduino UNO R3 / ATmega328P / 5V** 기준이며 다른 보드에는 그대로 적용하지 마세요.

**문 동작과 직접 설정한 MQ-135 원시 출력 변화에 반응하는 실습용 코드입니다. 실제 가스경보기나 화재경보기가 아니며 실물 검증 전입니다. 인증된 독립 경보기를 대체하지 않습니다.**

앱·스케치·노트북 프로그램은 `ZIPON_AUTO_V3` 한 버전으로 맞춥니다. 문 상태의 지속 확인과 LED·부저 자동 반응은 UNO에서 처리합니다. 앱은 기록·설정과 독립 출력 요청을 다룹니다. 가스 감시는 예열·기준 ADC를 사람이 확인한 뒤 **이번 USB 연결에서 직접 켜고 저장해야** 시작됩니다.

## 1. 전원을 모두 끄고 배선 변경

1. 노트북 USB와 외부 전원을 모두 분리합니다.
2. 먼지 센서의 6개 선, **먼지 센서 전용 150Ω 저항·220µF 콘덴서**를 제거합니다. **D8 LED의 직렬 저항은 유지**합니다.
3. D10은 더 이상 쓰지 않습니다. 먼지 센서가 사용하던 A5에 MQ-135의 AO를 연결합니다.
4. 사진 속 핀의 좌우 순서는 확정할 수 없습니다. 반드시 **실제 모듈의 핀 글씨**로 확인하세요. AO/DO, VCC/GND를 혼동하면 안 됩니다.

### MQ-135 권장 전원·신호 배선

| 모듈 핀 | 연결 |
|---|---|
| VCC | **별도의 안정된 5V DC 전원 +** |
| GND | 외부 전원 −와 **UNO GND 공통 연결** |
| AO 또는 A0 | **UNO A5** |
| DO 또는 D0 | 연결하지 않음 |

UNO는 노트북 USB로 전원과 통신을 받습니다. 별도 전원의 **+를 UNO 5V/VIN이나 USB 전원선에 연결하지 마세요.** 위 연결에서 두 전원의 양극은 합치지 않고 GND만 공통으로 합니다. 노출된 가정용 교류 전원은 다루지 말고, 정격이 확인된 절연형 저전압 어댑터와 적절한 커넥터를 사용하세요.

Winsen 사양서의 센서 히터 전력은 최대 950mW로, 5V에서 약 190mA에 해당하며 모듈 회로 전류는 별도입니다. 따라서 GPIO 핀이나 3.3V 핀으로 전원을 공급하면 안 됩니다. 공급 전류 여유를 위해 **안정화된 5V 1A급 전원**을 권장합니다. 실제 모듈 판매처의 허용 전원도 확인하세요. 센서 사양의 5.0V ±0.1V를 만족하는지 센서 쪽에서 측정해야 합니다.

UNO가 꺼진 상태에서 AO만 들어오지 않도록 **켜기: UNO USB → 센서 전원**, **끄기: 센서 전원 → UNO USB** 순서를 지키세요. 배선 변경은 둘 다 끈 상태에서 합니다. 모듈의 신호 전압이 UNO 입력 범위를 넘지 않는지도 확인하세요. 이 배선은 3.3V 보드용이 아닙니다.

### 그대로 유지하는 배선

| 부품 | 연결 |
|---|---|
| 표시 LED | D8 → **330Ω 직렬 저항** → LED 양극(+), 음극(−) → UNO GND |
| 작은 수동 피에조 부저 | 신호/+ → D6, − → GND |
| 초음파 Trig / Echo | D9 / D11 |
| HC-SR04 VCC / GND | 실제 부품이 5V HC-SR04형인지 확인 후 UNO 5V / UNO GND |

330Ω은 표시 LED용 설계값입니다. 기존 저항을 유지하려면 저항값과 LED 정격이 맞는지 먼저 확인하세요. LED와 부저를 저항 없이 같은 핀에 묶지 않습니다. UNO 공식 핀 자료의 I/O 핀 전류 한도는 20mA입니다. 부저 모델·소비 전류는 확인되지 않았으므로 D6 직접 구동이 가능한 **작은 수동 피에조**인지 확인하세요. 스피커·능동 부저·고전류 사이렌은 그대로 연결하거나 코드만 바꿔 사용하지 마세요. 별도 구동 회로 검토가 필요합니다. 이번 스케치에는 능동 부저 전환 설정이 없습니다.

`zipon-mq135-wiring.svg`가 이 연결의 기능별 회로도입니다. 모듈의 물리적인 핀 순서를 나타낸 그림은 아닙니다.

## 2. 예열과 측정 한계

- Winsen **MQ135 사양서 v1.6**의 표준 시험 조건은 **48시간 초과 초기 예열**입니다. 장기 보관 후에는 더 긴 안정화가 요구될 수 있습니다. 모듈 판매처의 초기 에이징·재인가 후 안정화 지침도 함께 따르세요.
- USB나 센서 전원을 잠깐 켰다고 예열·보정이 끝난 것이 아닙니다. 앱은 예열 완료나 정상·안전을 자동 선언하지 않습니다. 센서가 별도 전원을 쓰므로 보드 실행 시간으로 센서 예열 시간을 추정하지 않습니다.
- 히터가 들어 있는 부품입니다. 통풍되는 불연성 지지대에 고정하고, 맨손 접촉·가연물 접촉·액체·결로를 피하세요. 가연성/폭발성 분위기에서 실습하거나 장치에 안전을 맡기지 마세요.
- MQ-135는 여러 기체와 환경 조건에 반응합니다. 이 코드로 **특정 가스 종류, CO₂/CO/LPG 농도(ppm), 인체 안전, 누출·화재 여부**를 판정하지 않습니다. 저항·감도 곡선·기준값을 임의로 넣어 농도로 환산하지 않습니다.
- DO의 비교기·가변저항은 이번 코드에서 쓰지 않습니다. 가변저항을 돌려도 교정된 가스 농도 기준이 생기는 것이 아닙니다.
- 라이터 가스, 가스레인지, 차량 배기가스, 연소·연기·유해 기체로 시험하지 마세요. 제조사가 정한 절차와 적절한 장비가 없는 가스 방출 시험을 하지 마세요.

## 3. 아두이노 업로드

1. Arduino IDE에서 `zipon_uno/zipon_uno.ino`를 엽니다. https://www.arduino.cc/en/software
2. 실제 보드가 UNO R3인지 확인하고 **Arduino Uno**와 실제 USB 포트를 선택합니다.
3. 새 스케치를 업로드합니다. 추가 아두이노 라이브러리는 필요 없습니다.
4. **시리얼 모니터·시리얼 플로터를 닫습니다.** 노트북 연결 프로그램과 같은 포트를 동시에 사용할 수 없습니다.

스케치는 약 50ms마다 A5를 읽어 1초 평균을 만들고, 초음파는 약 100ms 간격으로 확인하며, 약 2초마다 원시값·감지 상태·출력 보고를 보냅니다. 무응답·범위 밖 초음파는 측정 실패이고 문 열림으로 만들지 않습니다. 전원 재시작 시 출력·문 보정·가스 감시는 꺼짐에서 시작하고 앱 설정이 별도로 전달됩니다. 설정은 보드의 RAM에만 있으며 전원을 끄면 사라집니다.

## 4. 노트북 설치와 앱 없는 USB 시험

Python 3.10 이상이 필요합니다. https://www.python.org/downloads/
압축을 푼 폴더에서 터미널을 엽니다. 아래는 **사용자 노트북**에서 실행하는 명령입니다.

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bridge.py --ports
.\.venv\Scripts\python.exe bridge.py --inspect --port COM3
```

`COM3`은 **예시**입니다. 포트 목록에 나온 실제 값으로 바꾸세요.

macOS/Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bridge.py --ports
.venv/bin/python bridge.py --inspect
```

프로그램이 물어보는 실제 USB 포트를 입력합니다. `--inspect`는 앱에 전송하거나 자동 감지 설정을 전달하지 않고 USB 원시값·보드 보고만 표시합니다. 종료는 `Ctrl+C`입니다. 보드 포트를 열면 UNO가 재시작될 수 있습니다.

ADC는 원시 값이며 전압은 UNO 기준 전압을 기본 5.0V로 가정한 근삿값입니다. 실제 AVcc를 측정했다면 `--adc-volts 4.98`처럼 **측정한 값**을 입력할 수 있습니다(4.98은 예시). 이 값은 센서 농도 보정이 아닙니다. 양 끝 ADC 0/1023도 숨기지 않고 표시하며 출력 범위·배선 확인 경고를 냅니다. `None`은 충분한 측정이 없거나 초음파 측정이 실패한 경우입니다. 선이 빠져 그럴듯한 값이 나오는 고장까지 소프트웨어로 확실히 검출하지 못합니다.

**새 스케치와 새 bridge.py를 함께 사용**하세요. 이번 형식은 `ZIPON_AUTO_V3` / 측정 `R` / 감지 사건 `E` / 실행 응답 `ACK`입니다. 이전 MQ-135 수동 버전 `ZIPON_MQ135_V2` / `G`와 먼지 버전 `ZIPON_USB_V1` / `S`는 받지 않습니다. 구형 앱 수신 호환과 과거 기록은 보존하지만 구형 USB 프로그램을 새 스케치와 섞지 마세요.

## 5. 앱과 연결

1. 게시된 HTTPS 집온 주소가 필요합니다. 아직 게시 전이라면 우선 USB 시험만 하고 앱 게시를 요청하세요. 미리보기 내부 주소는 넣지 않습니다.
2. **게시된 앱**을 가족 비밀번호로 열고 기기 관리에서 기기 연결 키를 발급받습니다. 이전 키를 바꾸면 기존 연결·대기 요청이 무효가 되며, 이미 켜진 부저를 물리적으로 끄는 것은 아닙니다.
3. `--inspect`를 빼고 `bridge.py --port COM3`처럼 실행합니다(실제 포트로 변경). 앞 명령과 같은 가상 환경의 Python을 사용합니다.
4. 앱 HTTPS 주소와 **기기 연결 키**를 입력합니다. 가족 비밀번호가 아닙니다. 입력한 키는 화면에 표시하거나 파일에 저장하지 않으며 보드에도 전달하지 않습니다.
5. 앱에 **가스 센서 출력 / MQ-135 / ADC·V**, 초음파 거리, 독립 LED·부저 상태가 표시되는지 확인합니다. 처음에는 가스 출력 감시가 꺼져 있습니다. 이전 다른 센서의 경보·설정은 임의로 지우거나 해제하지 않습니다.
6. 기기 관리에서 **문을 실제로 닫은 뒤** ‘문이 닫힌 지금 거리로 보정’을 누르고 기준값을 저장합니다. ‘문을 실제로 닫고 거리 기준을 확인했어요’를 수동 확인하는 방법도 있습니다. 홈에서 ‘저장한 설정 적용 응답 수신’을 확인합니다.
7. 안전한 환경에서 LED와 부저를 각각 ‘시험 2초’로 요청하고 **실제 빛·소리와 자동 종료**를 확인합니다. 가족과 반려견에게 먼저 알리세요. 부저는 한 번 더 확인합니다.
8. 제조사 예열·안정화 지침을 수행하고 안정된 ADC를 직접 확인합니다. 기준 ADC·상승 폭·지속 시간을 입력하고 예열·기준 확인 항목을 선택합니다. **‘이번 연결에서 감시 켜기 준비’ → ‘기준값 저장’**을 눌러야 합니다. 새 보드 응답까지 확인하세요. 가스를 방출해 시험하지 마세요.

**현재 사용자의 초음파는 이전 단독 검사에서도 `NO ECHO`였습니다.** 이 변경으로 실물 문제가 해결됐다는 뜻은 아닙니다. Trig D9·Echo D11, 정격 전원·공통 GND, 접촉 상태와 부품을 전원을 끄고 점검해야 합니다. 무응답이 계속되면 문 감지를 사용할 수 없습니다.

## 6. 자동 반응과 수동 출력의 규칙

| 동작 | 작성된 처리 |
|---|---|
| 문 상태 | 닫힘 기준 거리와의 차이가 허용값을 벗어나는지 지속 확인. 첫 확인값과 측정 실패 후 첫 복구값은 활동으로 세지 않는 기준 상태 |
| 문 동작 반응 | 보정 후 확정된 열림·닫힘 변화에 LED 0.5초·부저 0.2초. 기기 관리에서 사용 여부 변경 |
| 안심 시간 | 앱의 문 열림 알림에만 적용. 문 자동 LED·부저 반응 시간표가 아님 |
| 가스 출력 경고 | 기준 ADC + 상승 폭 이상이 설정 시간 이어지면 ‘가스 출력 이상·화재 여부 확인 필요’ 기록·자동 반응 |
| 가스 경고 복귀 | 기준 ADC + 상승 폭의 절반(정수 나눗셈) 미만이 같은 시간 지속. 복귀도 안전 판정이 아님 |
| 가스 측정 실패 | 0·충분하지 않은 측정은 실패로 보고하고 진행 중인 경고를 해제하지 않음. ADC 1023은 끝값 경고와 높은 출력으로 유지 |
| 가스 자동 반응 | LED는 약 0.4초 단위 점멸, 부저는 약 1초 단위 반복. 출력 경고가 유지되면 수동 시간과 별도로 계속될 수 있음 |
| LED·부저 켜기 | 서로 독립. 수동 설정 시간 5·10·15초, 최대 15초 |
| LED·부저 시험 | 해당 출력만 2초. 가스 자동 반응이 남아 있으면 시험 뒤 자동 반응으로 돌아갈 수 있음 |
| LED·부저 끄기 | 해당 출력의 수동 동작을 끝내고 자동 반응을 30초 억제. 30초 뒤 자동 복귀 |
| 자동 경고음 쉬기 | 자동 부저 반응만 60초 일시 정지. LED와 수동 시험은 계속될 수 있음 |
| 경고음 일시 정지 해제 | 자동 경고음 쉬기와 부저의 30초 끄기를 해제. 감지 경고가 남으면 즉시 소리가 재개될 수 있음 |

100 ADC 상승·10초는 **검증되지 않은 초기 실습 입력값**이며 화재·가스 농도 기준이 아닙니다. 센서 고장·단선도 그럴듯한 ADC를 낼 수 있어 완전히 검출하지 못합니다. 감시를 꺼도 기존 경고 플래그·기록이 즉시 안전으로 바뀌지는 않습니다. 보드 전원 재시작과 앱 기록 보존도 서로 다릅니다.

제어는 **앱 요청 → 전달 승인 → USB 명령 → 보드 실행 응답** 순서입니다. 요청·승인을 실제 실행으로 표시하지 않습니다. 실행 응답이 있어도 현재 출력은 새로운 측정 보고로 따로 확인합니다. 보드의 켜짐·꺼짐 보고는 소프트웨어의 핀 제어 상태이며 광센서·마이크로 빛·소리를 검증한 결과가 아닙니다. 짧은 문 반응은 2초 보고 사이에 끝날 수 있습니다.

## 7. 연결 중단·복구와 제한

- 노트북·프로그램·USB·인터넷이 유지돼야 앱 전송과 원격 제어가 됩니다. 가족 비밀번호는 보드로 보내지 않고, 연결 키도 노트북 메모리에만 둡니다. 키를 명령줄·소스·기록 파일에 쓰지 마세요.
- USB 연결 신호가 3초 끊기면 **수동 켜기만** 종료하도록 작성했습니다. **보드 전원이 남으면 이미 적용된 문·가스 자동 반응은 계속될 수 있습니다.** 인터넷 단절만으로 자동 경고가 꺼지지 않습니다. USB가 보드의 유일한 전원일 때 케이블을 빼면 보드 감지도 멈춥니다.
- 프로그램을 다시 시작하면 새 연결로 취급하며 가스 감시를 직접 다시 켜야 합니다. 보드가 재부팅되거나 USB가 끊기면 프로그램을 다시 실행하세요. 잠깐의 인터넷 장애는 새 측정으로 재시도합니다. 연결 키·버전·요청 거절은 프로그램을 중단할 수 있습니다.
- 새 측정만 전송하며 같은 자료 재전송으로 수신 시각을 연장하지 않습니다. 앱은 15초간 새 측정이 없거나 수신에 실패하면 현재 상태를 알 수 없다고 표시합니다. 감지 기록의 시간은 **앱 수신 시각**입니다. 끊긴 동안의 움직임·오래된 기록은 빠질 수 있고 30초를 넘은 과거 사건은 버립니다. 완전한 오프라인 기록 보관 기능은 없습니다.
- 제어 요청은 약 15초 안에 전달 승인을 받아야 합니다. 한 번 승인한 요청은 애매한 인터넷 결과 때문에 다시 켜지 않으며, 응답이 없으면 기한 만료·미확인으로 남깁니다. 새 USB 연결·연결 키 교체 뒤 이전 요청을 되살리지 않습니다.
- 연결 키 교체·앱 잠금·앱 종료는 보드의 물리적 전원 차단이 아닙니다. 앱 종료·휴대폰 잠금 중 문자·전화·푸시 비상 알림도 구현되지 않았습니다. 열린 화면의 알림도 브라우저·절전 조건에 영향을 받습니다.
- 실제 화재·누출이 의심되면 이 장치의 수치나 원격 출력에 의존하지 말고 현지 비상 대응 안내와 인증된 독립 경보기를 따르세요.
