# 집온 USB V4 설치 안내

이 장치는 **MQ-135 원시 ADC와 초음파 거리의 변화**를 관찰하는 실습용 프로토타입이에요. 화재·가스 종류·누출·농도(ppm)·안전·실제 사람의 출입을 판정하지 않아요. 인증된 독립 화재·가스 경보기와 보안 장치를 대체하지 않아요. **가스 방출·불꽃·연기로 시험하지 마세요.**

## 1. 기존 배선을 유지해요

전원을 모두 끈 뒤 부품에 쓰인 핀 이름으로 확인해요. 기능별 도면이며 모듈의 물리적 핀 순서를 뜻하지 않아요.

| 부품 | 연결 |
|---|---|
| MQ-135 AO | UNO A5 |
| MQ-135 DO | 연결하지 않음 |
| MQ-135 VCC | 별도 안정화 5V 전원 + |
| MQ-135 GND | 별도 전원 −와 UNO GND 공통 |
| HC-SR04 VCC / GND | UNO 5V / 공통 GND · 실제 5V형 확인 |
| HC-SR04 Trig / Echo | D9 / D11 |
| LED + | D8에서 330Ω 직렬 저항을 거쳐 연결 |
| LED − | GND |
| 작은 수동 피에조 + / − | D6 / GND · 모델·구동 전류·별도 구동 회로 필요 여부 확인 |

MQ-135는 VCC·GND·AO·DO 4핀 모듈을 전제로 해요. 6핀 금속 캡 단품용 도면이 아니에요. **별도 전원 +를 UNO 5V/VIN에 합치지 않아요.** USB 데이터 케이블로 UNO에 전원을 공급하고 두 전원은 GND만 공통으로 해요. 켤 때는 UNO USB부터, 끌 때는 센서 전원부터 끄세요. 실제 전원 안정성과 전류 조건은 별도로 확인해야 해요. D10·블루투스는 사용하지 않아요.

## 2. 새 스케치를 업로드해요

1. `zipon_uno_v4/zipon_uno_v4.ino` 원본을 Arduino IDE에서 열어요. 채팅에서 복사한 코드가 아닌 파일 원본을 사용해요.
2. 보드를 **Arduino Uno / ATmega328P**로 선택하고 실제 포트를 선택해 업로드해요. 추가 Arduino 라이브러리는 필요하지 않아요.
3. 업로드 완료 후 **시리얼 모니터·시리얼 플로터와 기존 Python 중계 프로그램을 모두 닫아요.**
4. 새 앱은 **9600 baud / ZIPON_USB_V4 / 줄 단위 JSON**이에요. 예전 115200 baud / ZIPON_AUTO_V3 코드·중계와 섞어 쓰지 않아요. 원본 V3 파일은 별도로 보존돼요.

## 3. 브라우저에서 직접 연결해요

배포된 Streamlit의 컴퓨터가 아닌 **UNO가 꽂힌 사용자의 컴퓨터**에서 앱을 열어요. 지원되는 데스크톱 Chrome·Edge 계열의 보안 연결(HTTPS)에서 사용해요. 로컬 개발의 localhost는 브라우저가 허용하는 보안 컨텍스트 예외예요. 휴대폰 직접 USB 연결은 보장하지 않아요.

가족 비밀번호로 들어간 뒤 `실시간 모니터링 → USB 연결`에서 포트를 선택해요. 새 코드 확인과 첫 측정을 기다려요. 앱이 자동으로 포트를 선택하거나 허가하지 않아요. 다른 앱이나 탭이 같은 포트를 점유하면 먼저 해제해요.

포트 권한이 막힌 내장 미리보기에서는 앱을 별도 탭에서 열어 확인해요. 지원하지 않는 브라우저, 잘못된 코드, 읽기 중단, 오래된 측정은 연결 오류·측정 없음으로 표시해요. 요청·실행 응답·보드의 출력 보고는 서로 달라요. **보드가 켜졌다고 보고해도 실제 빛·소리는 직접 확인해야 해요.**

## 4. 감시를 따로 시작해요

### 가스 원시 출력

- 제조사 안내에 따른 예열·환경 안정화와 기준 출력을 직접 확인해요. 앱은 예열 완료를 추정하지 않아요.
- 알림 설정에서 기준 ADC, 경보 ADC, 복귀 ADC와 각각의 지속 시간을 정해요. `기준 ADC ≤ 복귀 ADC < 경보 ADC`예요. 검증된 화재·안전 임계값은 제공하지 않아요.
- 설정을 적용한 뒤 **이번 USB 연결에서 가스 감시 시작**을 눌러요. 설정 저장만으로 켜지지 않아요.
- 약 1초 평균 출력의 지속 초과와 지속 복귀를 보드가 확인해요. 순간 변화로 반복 경보하지 않도록 기준을 나누었어요. 0·측정 실패로 기존 경보를 해제하지 않아요. 최대 ADC 1023도 농도로 환산하지 않아요.
- 보드 부팅 후 감시는 꺼져 있어요. 전원이 유지된 채 이미 가스 경보가 진행 중이라면, 새 USB 연결·수동 끄기로 그 경보를 지우지 않아요. 경보 중에는 가스 설정 변경을 거절해요.

### 거리 기반 출입 의심

- 알림 설정에서 출입 감시 사용, 기준 거리·변화량·지속시간·반복 방지 시간·출입 허용 요일과 시간을 적용해요. 초기 거리·시간 입력값은 **검증되지 않은 실습 시작값**이에요.
- 한국 시간으로 앱이 판정하며 컴퓨터의 날짜와 시계가 맞아야 해요. 시작 시각은 포함하고 종료 시각은 포함하지 않아요. 자정을 넘는 시간은 시작 요일을 따라요. 허용 시간이 하나도 없으면 모든 시간이 허용 시간 밖이에요.
- 모니터링에서 **이번 연결의 출입 감시 시작**을 눌러요. 처음 기준 거리 안의 지속 측정을 확인한 뒤 이탈을 감지해요. 최초 값·실패 후 첫 복구값·NO ECHO는 출입으로 세지 않아요.
- 허용 시간 밖의 지속 변화에서만 부저를 요청해요. 출입 의심 자체가 LED를 켜지는 않아요. 별도 수동 LED가 유효하면 LED는 켜질 수 있어요.
- 기존 안심 시간은 별도 화면 알림 규칙이며 출입 허용 시간표와 반대말이 아니에요. 화면을 숨기면 출입 감시를 종료하고 다시 시작해야 해요.

## 5. 출력 우선순위와 끊김

1. 가스 출력 경보: LED와 부저 모두 켜기.
2. 출입 의심: 부저 켜기. LED는 독립 수동 요청에 따르기.
3. 유효한 수동 요청: LED·부저 독립, 최대 15초·시험 2초.

수동 끄기는 수동 요청만 취소해요. 자동 경보를 잠시 억제하는 V3 기능은 V4에 없어요. 자동 상황이 끝나면 아직 유효한 수동 요청으로 돌아가고, 수동 요청의 시간을 자동으로 연장하지 않아요.

USB 통신 신호가 약 3초 끊기면 보드는 수동 출력과 앱 출입 경보를 종료하도록 작성돼 있어요. **전원이 남아 있으면 보드 자체 가스 감시·경보는 계속될 수 있어요.** 케이블·브라우저·인터넷·Streamlit 연결이 끊기면 앱 기록·제어는 지속된다고 보장하지 않아요. 앱은 연결 확인이 지연되면 USB를 종료해요. 열린 화면 안 알림만 있고, 앱 종료·컴퓨터 절전 중 비상 알림이나 완전한 오프라인 기록은 없어요.

## 6. 기록과 그래프

그래프는 접속 중 최근 600개 실제 측정만 표시하고 새로고침하면 비워져요. 실패 구간은 선을 끊어요. 이벤트는 당시 측정·출력 상태와 한국 시각으로 확인해요. 새 이벤트는 최근 2,000건을 보관하고 가져온 이전 기록은 이 제한으로 지우지 않아요.

외부 영구 저장소가 없으면 설정·기록은 해당 접속의 임시 자료예요. Streamlit의 로컬 파일을 영구 보관으로 안내하지 않아요. 전송 대기 중 닫은 기록은 사라질 수 있어요. 다른 컴퓨터에서는 저장된 기록·마지막 보고만 볼 수 있고 USB 원격 제어는 제공하지 않아요.

## 7. 실물 확인 체크리스트

- [ ] 실제 UNO 업로드 완료, 9600 V4 확인, 시리얼 모니터 종료
- [ ] 공통 GND·전원 분리·모듈 핀·저항·피에조 구동 조건 확인
- [ ] ADC 수신, 거리 수신 및 NO ECHO 구별
- [ ] LED·부저 각각 2초 시험, 실제 자동 종료 확인
- [ ] 끊김·다시 연결 후 읽기와 출력이 중복되지 않는지 확인
- [ ] 검증된 시험 절차에서 지속·복귀와 자동 경보 우선순위 확인
- [ ] 허용 시간 안·밖과 출입 반복 방지 확인

이전에 초음파 단독 검사에서도 NO ECHO가 보고됐어요. 소프트웨어만으로 원인이 해결됐다고 간주하지 않아요. 전원·접점·실제 핀·부품 상태 확인이 먼저예요. 소프트웨어 격리 검사·컴파일은 실물 시험 결과가 아니에요.
