# 이전 먼지 센서용 안내 — 현재 코드에 적용하지 마세요

사용자가 MQ-135로 변경했습니다. 현재 스케치·연결 프로그램·배선은 **MQ135-설치안내.md**를 따르세요. 아래 내용은 이전 GP2Y1014AU0F 연결의 참고 기록일 뿐이며 새 다운로드 묶음에는 포함하지 않습니다.

## 먼저 확인할 제한

- **실제 하드웨어로 검증하지 않은 실습용 코드**입니다. 원격 안전장치나 화재경보기로 쓰지 마세요.
- Sharp GP2Y1014AU0F 사양서 **7-8은 화재경보기 용도 사용을 금지**합니다. 이 연결 프로그램은 먼지 센서의 **원시 전압(V)**만 앱에 보내며, 농도·화재 여부로 환산하지 않습니다. 앱의 먼지 주의 기준과 화재 의심 알림은 이 센서에 적용되지 않습니다. 예전의 다른 센서 경보가 있었다면 자동 해제하지 않습니다.
- 그림 속 **Arduino UNO R3 / ATmega328P / 16MHz / 5V**를 가정했습니다. UNO R4·ESP32·다른 보드용 코드는 아닙니다. 초음파는 **HC-SR04 호환 Trig/Echo형을 가정**했으므로 실제 모델을 먼저 확인하세요.
- 부저 모델·전류는 확인되지 않았습니다. 기본 코드는 **작은 수동 피에조 부저**용 tone()입니다. 능동 부저는 스케치의 ACTIVE_BUZZER를 true로 바꿀 수 있지만, **구동 전류와 트랜지스터 회로 필요 여부를 먼저 확인**하세요. 스피커·고전류 사이렌을 보드 핀에 직접 연결하지 마세요.
- USB 데이터 케이블, 노트북의 인터넷 연결, Arduino IDE, Python 3.10 이상이 필요합니다. **블루투스 모듈·보드 Wi-Fi 모듈은 필요하지 않습니다.**
- 노트북이 켜져 있고 연결 프로그램이 실행 중이어야 합니다. 덮개 닫기·절전·전원/USB 분리·인터넷 장애 시 감시가 중단됩니다. 휴대폰은 게시한 앱을 볼 뿐 보드에 직접 연결하지 않습니다.
- 앱 종료·휴대폰 잠금 중 문자/전화/푸시 비상 알림은 구현되지 않았습니다. 브라우저가 열려 있어도 기기 절전 등의 영향을 받을 수 있습니다.

## 1. 전원을 분리하고 배선 확인

색상보다 **센서 핀 번호와 기능**을 기준으로 확인하세요. 첨부 그림을 해석한 연결입니다.

| 부품 | 연결 |
|---|---|
| 표시 LED | D8 → 기존 직렬 저항 → LED 양극, 음극 → GND |
| 작은 수동 피에조 부저 | 신호/+ → D6, − → GND (모델·전류 확인 필수) |
| 초음파 Trig | D9 |
| 초음파 Echo | D11 |
| 초음파 전원 | 해당 모델 사양에 맞는 전원과 공통 GND |
| 먼지 1번 V-LED | 5V에서 **150Ω 직렬 저항**을 거쳐 연결 |
| 먼지 2번 LED-GND | GND |
| 먼지 3번 LED 제어 | D10 |
| 먼지 4번 S-GND | GND |
| 먼지 5번 Vo | **A5** (디지털 D5 아님) |
| 먼지 6번 Vcc | 5V |
| 먼지 구동용 콘덴서 | **220µF**, +는 저항 뒤 V-LED 쪽, −는 LED-GND 쪽 |

LED D8에 단 저항과 먼지 센서의 150Ω 저항은 **서로 다른 부품**입니다. 전해 콘덴서 극성을 확인하세요. 모든 신호의 GND는 공통입니다. 부품을 꽂거나 바꿀 때 USB 전원을 빼세요. UNO의 `~` 표시는 PWM 지원 표시이며 코드에서는 6, 9, 11처럼 숫자로 씁니다.

## 2. 스케치 업로드

1. Arduino 공식 홈페이지에서 Arduino IDE를 설치합니다: https://www.arduino.cc/en/software
2. 이 묶음의 `zipon_uno/zipon_uno.ino`를 엽니다. 폴더와 파일 이름을 그대로 유지하세요.
3. 보드는 **Arduino Uno**, 포트는 연결된 실제 USB 포트를 선택합니다. 모델이 다르면 업로드하지 말고 먼저 알려 주세요.
4. 부저 종류·배선을 확인한 뒤 업로드합니다. 별도의 아두이노 라이브러리는 필요 없습니다.
5. 업로드가 끝나면 IDE의 **시리얼 모니터·시리얼 플로터를 닫습니다.** 연결 프로그램과 동시에 같은 포트를 사용할 수 없습니다.

보드를 켜거나 재시작하면 부저와 표시 LED는 꺼진 상태로 시작합니다. 앱에서 요청하기 전에는 먼지값이나 문 움직임 때문에 자동으로 부저를 켜지 않습니다.

## 3. 노트북 연결 프로그램 설치

Python 공식 설치: https://www.python.org/downloads/

압축을 푼 폴더에서 터미널을 엽니다. 아래 명령은 **사용자의 노트북**에서 실행합니다. 키를 명령어·코드·채팅에 넣지 마세요.

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bridge.py --ports
```

### macOS / Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bridge.py --ports
```

실제 포트 이름은 컴퓨터마다 다릅니다. 아래 `COM3`은 **예시**이며 위 목록에서 확인한 포트로 바꿉니다. macOS는 `/dev/cu.usbmodem…`, Linux는 `/dev/ttyACM…` 같은 형태일 수 있습니다. 포트가 보이지 않으면 데이터 케이블, 보드 드라이버, Linux의 포트 접근 권한을 확인하세요.

## 4. 앱 없이 USB부터 검사

Windows의 **포트 예시**:

```powershell
.\.venv\Scripts\python.exe bridge.py --inspect --port COM3
```

macOS/Linux는 같은 인수를 사용하되 실행 파일을 `.venv/bin/python`으로 바꿉니다.

- 실제 보드가 응답해야 연결됐다고 표시합니다. 시뮬레이션 값을 만들지 않습니다.
- 약 2초마다 먼지 출력 전압과 거리(cm)를 표시합니다. `None`은 측정 실패입니다. 손이나 평평한 물체를 가까이/멀리 옮겨 거리 변화를 확인하세요.
- 먼지 출력은 기준 전압을 5.0V로 가정한 근삿값입니다. 실제 AVcc를 측정했다면 `--adc-volts 측정값`을 추가할 수 있습니다. **보정된 먼지 농도가 아닙니다.**
- ADC 양 끝 값·부족한 측정·초음파 응답 없음은 실패로 보냅니다. 다만 아날로그 선이 빠져 떠 있는 상태가 그럴듯한 전압을 만드는 경우까지 소프트웨어로 확실하게 검출할 수는 없습니다. 정상 배선을 직접 확인해야 합니다.
- 불·연기·분진을 발생시켜 시험하지 마세요.
- `Ctrl+C`로 종료합니다. 이 검사 모드는 앱에 기록을 보내거나 부저를 켜지 않습니다.

## 5. 집온 앱과 연결

1. **집온 앱이 게시된 HTTPS 주소**가 필요합니다. 아직 게시하지 않았다면 먼저 게시를 요청하세요. 미리보기 내부 주소나 노트북 내부 주소를 임의로 넣지 마세요. 게시 후 미리보기 기록/키가 자동 이동하는 것은 아니므로, 게시된 앱에서 아래 작업을 합니다.
2. 게시된 앱을 가족 비밀번호로 열고 **기기 관리 → 기기 연결 키 만들기**를 누릅니다. 이미 쓰는 키를 바꾸면 기존 기기 연결·대기 명령이 무효가 되므로 주의하세요.
3. 다음 명령을 실행합니다. `COM3`은 실제 포트로 바꿀 **예시**입니다.

```powershell
.\.venv\Scripts\python.exe bridge.py --port COM3
```

4. 물어보는 **앱 HTTPS 주소**를 입력하고, 다음으로 **기기 연결 키**를 입력합니다. 키 입력은 화면에 나타나지 않으며 파일에 저장하지 않습니다. 아두이노에는 키나 가족 비밀번호를 보내지 않습니다. 매번 실행할 때 다시 입력합니다.
5. 첫 실제 측정값이 도착하면 앱의 연결 상태가 바뀝니다. 먼지 카드는 V 단위의 **먼지 센서 출력**으로 바뀌며 화재 여부를 판단하지 않는다고 표시합니다.
6. 프로그램이 오류를 표시하고 종료되면 원인을 확인한 뒤 다시 실행하세요. 자동 재연결·자동 시작은 하지 않습니다. 과거 측정값을 쌓아 두었다가 최신값처럼 다시 보내지도 않습니다.

연결 키가 틀리거나 주소가 잘못되면 진행하지 않습니다. HTTPS 인증서 검증은 끄지 않으며, 다른 주소로 이동시키는 응답도 따라가지 않습니다. 회사 구성원만 열 수 있도록 제한된 앱은 이 연결 프로그램이 접근하지 못할 수 있습니다. 가족 비밀번호 보호는 유지하되 기기 통신이 가능한 공개 주소가 필요합니다.

## 6. 현관문과 부저 확인

1. 문이 닫혔을 때의 거리를 노트북 출력으로 확인하고 **기기 관리 → 센서 기준값과 사이렌 시간**에서 닫힘 거리와 열림 판단 거리 차이를 맞춥니다. 센서가 문 움직임을 실제로 구분하도록 고정해야 합니다. 임의의 기본값은 검증된 설치값이 아닙니다.
2. 문을 열고 닫으며 앱 기록을 확인합니다. 한 번의 측정이 아니라 이어진 측정으로 판단하므로 수 초 늦을 수 있습니다. 초음파 범위 밖으로 문이 사라지면 이 코드는 `측정 실패`로 보냅니다. 이를 무조건 문 열림으로 판단하지 않습니다. 열린 문에서도 측정 가능한 설치 구조가 필요합니다.
3. 사이렌 시간을 우선 **5초**로 설정합니다. 주위 사람·동물에게 알리고 앱에서 **사이렌 울리기 → 재확인**을 진행합니다.
4. **실제 부저 소리와 D8 LED**를 눈앞에서 확인합니다. 앱의 실행 응답은 연결 프로그램의 소프트웨어 응답이지 소리가 났다는 증거가 아닙니다. 앱에 실행 응답이 먼저 기록된 뒤 USB 전송이 실패하면 소리가 나지 않을 수 있습니다.
5. 중지 버튼, 지정 시간 종료, 연결 프로그램 종료를 확인합니다. 보드는 최대 15초 요청만 허용하고, 노트북의 연결 신호가 3초 끊기면 끕니다. 이 소프트웨어 제한은 물리적인 독립 안전차단 장치가 아닙니다. 고장·배선·정확한 타이밍은 현장에서 별도 검증해야 합니다.
6. USB 또는 인터넷을 끊으면 새 측정값이 멈추고 앱은 약 15초 후 연결 끊김으로 바뀌는지 확인합니다. 최신값이 없을 때 정상이라고 표시하면 사용을 중단하세요.

실제 안전을 이 장치에 의존하지 마세요. 인증된 독립 화재경보기와 직접 확인 수단이 필요합니다.

## 코드 구조와 통신

- `zipon_uno/zipon_uno.ino`: UNO 센서 측정, 부저·LED 제어, 자동 종료. 먼지 LED는 10ms 주기, 약 0.32ms 구동, 약 0.28ms 샘플링을 목표로 합니다. ADC 변환이 끝날 때까지 LED를 켜 두는 단순 analogRead 예제를 쓰지 않았습니다. 실제 파형은 오실로스코프로 확인해야 합니다.
- `bridge.py`: USB 읽기와 연결 신호는 별도 스레드, 실제 최신 측정만 앱에 전송. 네트워크 응답을 기다려도 보드 종료 타이머는 독립적입니다. 읽기 실패/보드 재시작은 종료하며 재실행할 때 새로운 연결 번호를 만듭니다.
- `requirements.txt`: 노트북에서 필요한 pyserial 버전.
- `HELLO 세션` → `READY 세션 ZIPON_USB_V1`, `S 세션 번호 ADC 거리mm`, `PING 세션`, `START 세션 요청번호 초`, `STOP 세션 요청번호`, `OFF`, `ACK 세션 요청번호 상태`를 줄바꿈으로 주고받습니다. 임의로 시리얼 명령을 입력하면 앱 기록과 불일치할 수 있으므로 하지 마세요.
- 앱 전송은 기존 `/api/device/telemetry`, `/api/device/commands/요청번호/ack`를 사용합니다. 기기 키는 전송 헤더에만 넣습니다. `dustSensor`는 `GP2Y1014AU0F`, `dustUgM3`는 항상 null, `dustVoltageV`는 측정 전압 또는 null입니다.
- 시작은 기한·최근 USB 측정 확인 → 앱의 시작 승인 응답 확인 → USB 시작 명령 순서입니다. 이미 승인됐거나 불확실한 요청은 다시 켜지 않습니다. 보드의 실제 종료 응답을 받은 뒤 완료를 보냅니다. 응답 손실 시 실행이 누락되거나 앱과 실제 상태가 다를 수 있어 현장 확인이 필요합니다.
